# NexusOS

Операционная система с нуля: свой UEFI-бутлоадер (на чистом C, без gnu-efi
и без mingw) + своё ядро + драйверы + встроенный шелл с программами.
Собирается одним `gcc` + `binutils` — никаких внешних SDK не требуется
(кроме `mtools`/`dosfstools`, если нужен настоящий диск для тестов —
см. "Сборка и запуск").

## Статус на сейчас

Система загружается через UEFI, поднимает своё ядро, показывает шелл,
реагирует на клавиатуру, знает время с момента загрузки, видит устройства
на шине PCI и умеет ЧИТАТЬ настоящий диск через AHCI + FAT32.

`boot/efi/boot.c` — сам бутлоадер:
- запускается прошивкой как `\EFI\BOOT\BOOTX64.EFI`;
- находит Graphics Output Protocol (framebuffer);
- открывает диск, с которого сам загрузился, читает `\kernel.elf`;
- парсит ELF64, раскладывает `PT_LOAD`-сегменты по физическим адресам;
- получает финальную memory map, зовёт `ExitBootServices()`;
- прыгает в `kernel.elf`, передав `nexus_boot_info_t` (framebuffer + memory map).

`boot/kernel/` — ядро:
- своя GDT и IDT на все 32 исключения CPU + 16 IRQ, с "экраном паники"
  при исключении.

`vendor/` — драйверы железа (кроме диска, см. `ms/` ниже):
- текст на экране — свой битмап-шрифт 8×16, сгенерирован из настоящего
  TTF (`vendor/display/`);
- 8259 PIC перепрограммирован под вектора 32-47 (`vendor/interrupt/`);
- PS/2-клавиатура (`vendor/input/`);
- PIT-таймер, 100 Гц, считает тики с момента загрузки (`vendor/timer/`);
- CPUID (`vendor/cpu/`).

`ms/` (mount storage) — диск и файловые системы:
- перечисление устройств на шине PCI (`ms/storage/pci.c`);
- AHCI-драйвер — находит SATA-контроллер и диск, читает секторы через
  DMA (`ms/storage/ahci.c`, **только чтение**, см. предупреждения в файле);
- FAT32 — монтирование и чтение файлов/директорий с настоящего диска
  (`ms/fs/fat32.c`, **только чтение**, без длинных имён).

**Известное упрощение**: ядро пока работает на paging, который оставила
UEFI-прошивка (identity map физическая=виртуальная память). Своя таблица
страниц — Milestone 5, см. дорожную карту.

## Шелл и встроенные программы

Ядро показывает приглашение `nexus> ` и понимает команды (полный список —
`help`):

**Инфо**: `neofetch`, `sysinfo`, `about`, `whoami`, `version`, `date`
(CMOS RTC), `history`, `colors`

**Текст**: `echo`, `reverse`, `len`, `upper`, `lower`, `title`

**Математика**: `calc <a> op <b>`, `sum <n1> <n2>..`, `hex <n>`, `dec <n>`,
`isprime <n>`, `fib <n>`

**Файлы — ramfs, в ОЗУ, сбрасывается при перезагрузке** (`system/apps/vfs.c`):
`ls`, `pwd`, `cd`, `mkdir`, `rmdir`, `touch`, `rm`, `cp`, `mv`, `cat`,
`less` (= cat), `head [n]`, `tail [n]`, `grep <w> <file>`,
`diff <f1> <f2>`, `find <name>`, `write`, `append`, `wc`, `df`, `du`

**Файлы — настоящий FAT32-диск, ТОЛЬКО ЧТЕНИЕ** (`ms/fs/fat32.c`):
`diskls [path]`, `diskcat <path>` — можешь прочитать, например, свой
собственный `diskcat /kernel.elf` (будет "грязно", это бинарник, но
работать будет) или что угодно, что докинешь на диск через `mcopy`.

**Железо**: `lspci`, `uptime`, `beep` (PC speaker), `uname`

**Питание**: `reboot`, `shutdown` (ACPI-трюк QEMU, порт 0x604, на
реальном железе может не сработать — тогда падает обратно на `halt`),
`halt`

**Справка**: `man <command>`, `help`

Всё это выполняется синхронно внутри обработчика прерывания клавиатуры
(`system/shell.c`) — процессов и очереди событий пока нет. Как только они
появятся (Milestone 9), шелл и встроенные программы переедут в userspace.

## Драйвер клавиатуры переписан — была реальная проблема на живом железе

Ты сообщил, что при загрузке с флешки на реальном ноутбуке клавиатура не
работала вообще — ни встроенная, ни USB. Причина нашлась в
`vendor/input/keyboard.c`: старая версия просто читала порт 0x60 по IRQ1,
ничего не настраивая заранее, полагаясь, что контроллер i8042 уже в
нужном состоянии (в QEMU это работает — эмулированный контроллер
снисходителен). На части реального железа после `ExitBootServices()`
конфигурация контроллера (в первую очередь **бит трансляции** scan code
set 2 → set 1, без которого наша таблица скан-кодов читает не те байты)
могла быть не той, что мы ожидаем.

Добавил `keyboard_init()` (вызывается в `kmain()` до `sti`), которая
честно проходит последовательность инициализации 8042: выключает оба
PS/2-порта, сбрасывает буфер, читает/правит configuration byte
(включает IRQ1, включает трансляцию, включает clock порта 1), снова
включает порт клавиатуры и явно шлёт самой клавиатуре команду "начать
сканирование". Это должно чинить и встроенную клавиатуру ноутбука (она
почти всегда PS/2-совместима через embedded controller), и USB — если у
тебя включён USB Legacy Support в BIOS (см. ниже).

## Про HDMI и USB-клавиатуру — важный технический нюанс

**HDMI уже работает.** Экран, который рисует `vendor/display/console.c`,
это UEFI Graphics Output Protocol (GOP) — линейный framebuffer, который
прошивка уже настроила ДО того, как включился наш код. Разъём (HDMI,
DisplayPort, VGA) для нас совершенно не важен — для нас это просто
массив пикселей по фиксированному адресу. Написать отдельный
"HDMI-драйвер" с нуля — это в реальности написать драйвер GPU
(Intel/AMD/Nvidia) со своим mode-setting, что per-vendor задача на
многие месяцы/годы даже для профессиональной команды.

**USB-клавиатура** — после фикса выше должна заработать через режим
"USB Legacy Support" в UEFI/BIOS (включён по умолчанию почти everywhere):
чипсет сам эмулирует PS/2-клавиатуру на портах 0x60/0x64. Настоящая,
"родная" поддержка USB (без опоры на эмуляцию прошивки) — это отдельный
драйвер контроллера (на современных машинах — xHCI) плюс HID-класс
поверх него, реалистично на несколько недель работы. Если после
пересборки окажется, что всё ещё не работает — распишу xHCI отдельным
большим милстоуном.


## Как собран бутлоадер (без сети, без gnu-efi/mingw)

GNU `ld` умеет напрямую собирать PE32+/EFI образ через эмуляцию `i386pep`
(обычно используется для mingw), если исходники скомпилированы как
`-ffreestanding -fpic -mno-red-zone -fshort-wchar`, а функции на границе
с прошивкой помечены `__attribute__((ms_abi))` — потому что UEFI
использует calling convention Windows x64, а не System V, который GCC
использует по умолчанию на Linux.

## Сборка и запуск

```bash
make iso     # соберёт BOOTX64.EFI + kernel.elf, разложит в iso/ (структура ESP)
make run     # iso + соберёт build/fat.img (сырой FAT32, mkfs.vfat) + запустит QEMU
             # (нужны dosfstools, mtools, qemu-system-x86_64, OVMF)
```

Раньше `run` не зависел от `iso` и падал, если запустить его первым —
теперь это исправлено (`run: iso`).

Зависимости:

```bash
# Ubuntu/Debian
sudo apt install qemu-system-x86 ovmf dosfstools mtools

# Arch
sudo pacman -S qemu-full edk2-ovmf dosfstools mtools

# Fedora
sudo dnf install qemu-system-x86 edk2-ovmf dosfstools mtools
```

`make run` ищет `OVMF_CODE_4M.fd` в `/usr/share/OVMF/` и `OVMF_VARS.fd`
рядом с `Makefile` — если его нет, скопирует сам из
`/usr/share/OVMF/OVMF_VARS_4M.fd`. Поправь пути в `Makefile`, если у
тебя они другие (разные дистрибутивы иногда кладут OVMF в другое место).

Хочешь подложить свои файлы на диск для `diskls`/`diskcat` — после
`make run` (или вручную теми же командами до запуска qemu) докинь их
через `mtools`:

```bash
mcopy -i build/fat.img путь/к/файлу ::/имя_на_диске
```

## Дорожная карта

- [x] Milestone 1 — EFI-бутлоадер, вывод текста, поиск GOP
- [x] Milestone 2 — бутлоадер грузит `kernel.elf`, ExitBootServices, передача управления
- [x] Milestone 3 — ядро: GDT, IDT, framebuffer-консоль, PS/2-клавиатура
- [ ] Milestone 4 — физический аллокатор памяти (bitmap/buddy) на основе UEFI memory map
- [ ] Milestone 5 — своя виртуальная память: 4-уровневый paging, higher-half ядро
- [x] Milestone 6 (частично) — таймер (PIT) есть; вытесняющего переключения задач ещё нет
- [x] Milestone 7 (частично) — AHCI-диск есть (только чтение); NVMe нет
- [x] Milestone 8 (частично) — FAT32 есть (только чтение); записи и своего формата ФС нет
- [ ] Milestone 9 — user mode, syscalls, процессы, загрузка бинарников из `userdata/apps/`
- [ ] Milestone 10 — шелл переезжает в userspace как обычный процесс
- [ ] (не по плану, по запросу) — реальный USB-стек (xHCI + HID), если после
      проверки Legacy-режима окажется, что он правда нужен

## Архитектура: 5 разделов проекта

По аналогии с разделами Android (boot/vendor/system/userdata) плюс
отдельный раздел под диск (`ms` — mount storage, по аналогии с `vold`):

| Раздел | За что отвечает |
|---|---|
| `boot/` | Всё, что поднимает машину — см. подпапки ниже |
| `vendor/` | Драйверы железа (кроме диска — см. `ms/`), по категориям |
| `system/` | Встроенные программы и сервисы (`shell.c`, `apps/*`) |
| `userdata/` | Заготовки под пользовательские данные и программы |
| `ms/` | Mount storage: диск и файловые системы |

`boot/` разложен на сам бутлоадер и ядро, которое он запускает —
это два разных мира (разный ABI, разный формат бинарника):

```
boot/
├── efi/            — сам UEFI-бутлоадер: boot.c, efi.h, elf.h (PE32+, MS ABI)
└── kernel/         — ядро: entry.S, kernel.c, gdt.*, idt.*, kstate.*, kernel.ld (ELF, SysV ABI)
```

`vendor/` разложен по категориям устройств:

```
vendor/
├── io.h            — inb/outb/inl/outl (общий примитив для всех драйверов ниже)
├── input/          — keyboard.c/h (PS/2)
├── display/        — console.c/h (framebuffer) + font8x16.h
├── interrupt/      — pic.c/h (8259 PIC)
├── timer/          — pit.c/h (8253/8254 PIT)
└── cpu/            — cpu.c/h (CPUID)
```

`ms/` разложен на драйверы диска и файловые системы поверх них:

```
ms/
├── storage/        — pci.c/h (перечисление PCI) + ahci.c/h (SATA, только чтение)
└── fs/             — fat32.c/h (только чтение, без длинных имён)
```

**Важная честность**: на реальном диске это пока НЕ отдельные разделы,
как в Android — весь код `boot/kernel/` + `vendor/` + `ms/` + `system/`
линкуется в один `kernel.elf`. Разделение сейчас — это организация
исходников: чёткая граница ответственности, а не независимые загружаемые
компоненты. Настоящее разделение (когда `system/` и `userdata/` станут
реальными разделами/директориями на диске, откуда ядро грузит
исполняемые файлы) наступит вместе с записью в файловую систему и user
mode (Milestone 9).

## Структура проекта

```
NexusOS/
├── boot/
│   ├── efi/                   — EFI-бутлоадер (PE32+, MS ABI)
│   └── kernel/                — ядро (ELF, SysV ABI): entry, GDT, IDT, kstate
├── vendor/                    — драйверы по подпапкам (см. архитектуру выше)
├── ms/
│   ├── storage/                — драйверы диска (PCI, AHCI)
│   └── fs/                     — файловые системы (FAT32)
├── system/
│   ├── shell.c/h                — построчный ввод, диспетчер команд
│   └── apps/                    — все встроенные программы (см. список команд выше)
├── userdata/                  — заготовки: video/ audio/ downloads/ photos/ apps/
├── common/                    — boot_info.h, mem.c (общее для boot/efi и boot/kernel)
├── extras/                    — НЕ часть ОС, см. extras/README.md
├── Makefile
└── iso/, build/                — артефакты сборки
```
