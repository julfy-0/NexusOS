# userdata/

Зарезервировано под пользовательские программы и данные — по аналогии с
`/data` в Android (или `/home` в Linux).

```
userdata/
├── video/       — видеофайлы (нужен видеокодек — см. video/README.md)
├── audio/       — аудиофайлы (нужен драйвер звука — см. audio/README.md)
├── downloads/   — скачанное (нужен сетевой стек — см. downloads/README.md)
├── photos/      — изображения (ближе всего к реальности — см. photos/README.md)
└── apps/        — ПОЛЬЗОВАТЕЛЬСКИЕ программы (не встроенные, см. apps/README.md)
```

**Честно о статусе**: у NexusOS пока нет файловой системы с поддержкой
записи (есть только чтение FAT32, см. `ms/fs/fat32.c`), нет
процессов и нет загрузчика исполняемых файлов в userspace — всё ядро
линкуется в один `kernel.elf`. Поэтому все папки выше пока пустые
заготовки: реальным разделом на диске, куда можно что-то положить и
прочитать обратно из ОС, `userdata/` станет вместе с записью в ФС и
user mode.

Что уже РЕАЛЬНО работает и с чем можно поиграть прямо сейчас — это
`system/`, где живут встроенные программы, вкомпилированные в ядро
(`neofetch`, `calc`, `ls`, `cat` и т.д., см. `help` в шелле), и команды
`diskls`/`diskcat`, которые читают настоящий FAT32-диск (пока только на
чтение).

Дальше по дорожной карте (см. корневой README.md):
- Milestone 8 (запись в файловую систему) — `userdata/` станет реальным
  разделом, а не просто директорией в исходниках;
- Milestone 9 (user mode + syscalls) — `userdata/apps/` начнёт принимать
  откомпилированные пользовательские программы, которые ядро грузит и
  запускает как отдельные процессы — в отличие от `system/apps/`, где
  программы вкомпилированы прямо в ядро и не могут быть добавлены без
  пересборки `kernel.elf`.
